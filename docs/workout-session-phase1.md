# 训练记录第一阶段（前端）约定

范围：训练填写页、动作目标编辑、本次训练总览。未修改数据库结构、云函数、安全规则。
相关代码：`services/workout-session.uts`（模型/校验/本机存储）、`services/workout-adapter.uts`（云端字段映射）、
`components/gym-workout-overview`、`gym-workout-sheet`、`gym-target-editor`、`gym-rir-picker`、`pages/workout/workout`。

## 流程

首页开始/继续训练 → 本次训练总览 → 添加/编辑动作（弹层）→ 保存动作返回总览 → 结束训练 → 摘要。

- 保存动作：只保存当前填写状态到本机并返回总览，不结束整场训练，不自动完成任何组。
- 结束训练：先提示未完成组；只统计已完成的组；未完成组不会被自动标记完成。
- 退出页面不等于结束训练；训练保持“进行中”，再次进入会恢复，包括未保存的动作编辑。

## 本机存储（非云端同步）

| key | 内容 |
| --- | --- |
| `gymConsume.workoutSession.v1` | 当前训练会话（进行中或刚结束） |
| `gymConsume.workoutSessionHistory.v1` | 已归档的历史会话，最多 30 条 |

key 带版本号；版本不匹配时读取为空且不删除原数据。不读写任何已有缓存。

## 字段

会话 `WorkoutSession`：`status`（active/finished）、`date`（开始日期）、`cloudStatus`（none/pending/synced/failed/skipped）、`editing`（未保存的动作编辑草稿）。

动作 `SessionExercise`：`target`（本次目标，独立保存）、`weightRequired`（是否要求重量 > 0）、`cloudSynced`。

目标 `ExerciseTarget`：`workSets` 正式组数、`repsMin/Max`、`rirEnabled` + `rirMin/Max`（可不设置）、`restSeconds`。

组 `SetEntry`：
- `id` 稳定 ID，删除其他组不会错位。
- `kind`：`work` 正式组 / `warmup` 热身组。缺失时按 `work` 读取，不改写原数据。
- `weight` / `reps`：字符串，空串表示未填写；重量最多 2 位小数，次数为正整数。
- `rir`（实际 RIR，与目标 RIR 独立）：`''` 未填写｜`'0'`–`'4'`｜`'5+'`｜`'unsure'` 不确定。不自动继承目标或上一组。
- `done`：完成状态。完成时需通过校验；RIR 选填，不参与校验。

## 统计约定

- 完成正式组数 = `kind=work` 且 `done` 且数据合法的组；热身组不计入目标组数、容量与云端。
- 容量 = 已完成正式组的 重量 × 次数。
- 目标 3 组、实际完成 2 组是合法状态；修改目标不会增删组，也不会改动重量、次数、RIR、完成状态。
- 重量要求：核心类和自重动作（`back-01`、`chest-04`、`core-01`、`core-02`）重量可空，其余需 > 0。
- 没有任何已完成组时结束训练：直接丢弃，不产生记录。只完成热身组：保存在本机，不提交云端。

## 云端（现有接口，未扩展）

结束训练时经 `saveExerciseLog` 提交，仅包含已完成正式组的 `{ weight, reps, done }`（沿用现有 workouts 文档，
按训练开始日期累加）。以下仅在本机：目标、组类型/热身组、实际 RIR、组 ID。
逐动作提交并标记 `cloudStatus`/`cloudSynced`，失败可重试且不会重复写入。后端支持新字段后只需改 `toCloudLog`。

## 第二阶段（前端）：首页周目标与训练日历

代码：`services/gym-calendar.uts`（日期 / 周 / 月 / 记录合并，纯逻辑）、`services/weekly-goal.uts`（周目标）、
`services/gym-days.uts`（详情页数据加载）、`components/gym-dashboard`、`gym-week-goal-editor`、`gym-day-detail`、`pages/day-detail`。
测试：`node scripts/test_home_stats.mjs`（Node 22.6+，无需安装依赖；在 4 个时区下运行）。

### 统一的日期与统计口径（首页周进度、日历、月统计、连续天数共用）

- 日期是用户本地自然日的 `YYYY-MM-DD` 字符串，全部通过 `new Date(y, m, d)` 构造，不经过 UTC / `toISOString`；周一至周日为一周。
- **训练日**：存在至少一条“已结束且至少有一个已完成正式组”的记录的日期。同一天多场训练只计 1 天。
- **不计入**：进行中的训练（`status=active`）、没有完成组的训练、仅完成热身组的训练（`cloudStatus=skipped`）、未完成的组。
- **进行中**单独展示：日历用橙色圆点（落在训练开始日期），详情卡标记“进行中”，不计入周进度 / 月统计 / 连续天数；结束后才计入。
- 周进度 = 本周（周一至周日）训练日数 / 本周目标；`remaining` 最小为 0，超出目标时另给 `extra`（“已超额完成 N 天”）。
- 周训练容量、月训练天数、连续训练天数都基于同一批“计入”的记录。

### 记录来源（不伪造云端同步）

| 来源 | 展示 | 说明 |
| --- | --- | --- |
| 云端 `workouts`（每天一条，同天多次已合并） | “已完成 · 云端记录” | 真实云端数据 |
| 本机 `finished` 且 `cloudStatus` 为 `pending`/`failed` | “待提交”/“提交失败” | 计入训练日，但标注仅在本机 |
| 本机 `finished` 且 `cloudStatus=skipped` | “仅热身” | 不计入训练日 |
| 本机 `active` | “进行中” | 本机草稿，不计入 |
| 本机 `synced` | 不重复展示 | 已包含在云端记录；仅当云端加载失败时作为回退展示，并提示“仅显示本机记录” |

云端按天合并后无法区分同一天的多场训练，因此云端那天只显示一条；本机的待提交 / 进行中训练单独列出。

### 周目标（仅本机，未同步云端）

- 存储 key `gymConsume.weeklyGoal.v1`：`{ version, changes: [{ week(生效周周一), goal(1–7), setAt }] }`，带版本号，非法条目读取时丢弃。
- 某周使用的目标 = 生效周不晚于该周的最近一次变更。**没有变更记录的更早周次为“未知”（`known=false`）**，不会推算历史目标或达标情况；
  从未设置过时本周使用默认 4 天并标注“（默认）”。
- 本周生效：记录生效周 = 本周，并取消尚未生效的下周变更；下周生效：记录生效周 = 下周一，本周仍用原目标，首页提示“10月26日（下周一）起目标改为每周 N 天”。
  到生效周后按日期自然切换，无需任何后台任务。
- 目标变更只影响本周及之后，旧周次的目标不被覆盖。

### 首页

- 日历：今天（描边）、选中日期（实心）、有训练（浅绿 + 圆点）、进行中（橙点）、未来日期（灰）可同时区分；只能选择当月内的日期；不允许翻到未来月份。
- 所选日期下列出当天全部记录；无记录显示“这一天没有训练记录 / 还没到”，不使用“休息日”；移除了没有对应功能的“查看计划”按钮。
- 点击记录进入 `pages/day-detail`（动作与组明细）；点击“进行中”记录继续该训练。
- 开始 / 继续：有进行中的训练时显示“继续训练”，进入已有训练，不新建；没有时显示“开始今日训练 · M月D日”。训练总是记录在今天，
  查看历史日期时按钮上方会提示这一点；进行中的训练不是今天开始时也会注明开始日期。暂不支持补录历史日期。
- 注意：`<script setup>` 里解构 `defineProps` 得到的是一次性快照，需要响应变化时使用 `props.xxx`。

## 第三阶段（前端）：数据页训练热力图与动作表现

代码：`services/gym-insights.uts`（热力图 / 趋势 / 动作选项 / 概览 / 部位分布，纯逻辑）、`services/gym-insights-data.uts`（本地偏好）、
`services/gym-demo.uts`（演示数据与开关）、`components/gym-analytics`（页面容器）、`gym-heatmap`、`gym-exercise-performance`、`gym-exercise-picker`。
`gym-stats.uts` 只保留云端记录类型与日期工具；旧的 `calcHeatmap / calcExerciseTrend / calcOverview / calcMuscleStats / setsPerDate` 已删除，避免出现第二套统计口径。

### 数据来源与口径

数据页、首页使用同一份 `DayEntry`（云端 + 本机已结束训练，见第二阶段），只统计“已结束且有已完成正式组”的训练；
热身组、未完成组、进行中训练、仅热身训练都不参与。概览卡片由原来的“总训练 N 次”改为“训练天数”（与首页周 / 月口径一致）。

- **热力图**：12 周 × 周一至周日，按真实日期生成，最后一列是本周；本周未到的日期用虚线框标识，与“过去无记录”（灰色实心）区分；今天有绿色描边。
  颜色分档集中在 `HEAT_STEPS`：0 / 1–5 / 6–10 / 11–15 / 16+ 组（仅是展示分档，不是质量评级）。月份标识来自“该周包含 1 日”，第一列补所在月份。
  点击日期在卡片内展开当天记录（日期、训练列表、每个动作的正式组数、“查看训练记录”进入 `day-detail`；进行中的训练进入训练页）。
- **动作表现**：按稳定的动作 ID 关联；杠铃卧推 / 哑铃卧推等变式是不同 ID，不按名称合并。一次训练中一个动作 = 一个数据点
  （云端：`workouts.exercises` 里的一条 `ExerciseLog`；本机：一场训练里的一个动作），按日期 → 云端在前 / 本机在后 → 结束时间排序，
  没有训练的日期不补 0，同一天多次以“第 N 次”区分（本机训练在详情里显示结束时间；云端按天合并，没有时间）。
  - 最高工作重量 = 该次训练该动作已完成正式组中的最大记录重量；并列时详情列出全部对应记录（`重量 × 次数`），没有“最佳组”算法，也不计算提升百分比。
  - 训练容量 = Σ（记录重量 × 次数），详情显示公式。按记录重量直接计算，不对哑铃单只 / 双只做换算。
  - 单位：目前记录里没有单位字段，统一视为 kg（`WEIGHT_UNIT`）；将来支持 lbs 需要先在记录里增加单位。
  - 时间范围：近 4 周 / 近 12 周 / 近 1 年（默认近 12 周）；“最近一次记录”与时间范围无关。
  - 不支持：`isWeightRequired` 为 false 的动作（引体向上、双杠臂屈伸、核心类）没有明确的重量口径（外加负重 / 辅助重量），不画重量类趋势，只展示最近一次的次数。
  - 缺失值：重量或次数无效（≤0，旧数据可能出现）的组不计入，该次训练的点若无有效组则不画，并提示“N 次缺少有效重量”。
- **旧数据兼容**：缺少 `exerciseId` 的云端旧记录不按名称猜测，不归属任何动作，只在动作表现底部提示条数；仍计入热力图（它按组数统计，不依赖动作）。
  只有汇总字段（没有动作明细）的旧记录计入热力图 / 训练天数，但不参与部位分布和动作表现。
- **动作选择**：复用云端动作库 `exercises`；有记录的动作在前（最近训练日期倒序），无记录的动作可选，图表显示空状态；可按名称 / 部位 / 拼音搜索；
  只出现在记录里、已不在动作库的动作也会列出并标注。动作库加载失败时只列出有记录的动作。
- **本地偏好**：当前动作 / 指标 / 时间范围保存在本机 storage `gymConsume.insightPrefs.v1`（演示模式用 `.demo.v1`），不上传云端；非法值回退默认，保存的动作不存在时回退到最近训练过的动作。
- **部位分布**保留，仍按动作所属部位（胸 / 背 / 腿 / 其他）统计近 90 天的已完成正式组数；它与“动作表现”是不同用途，互不推断。

### 演示数据

`services/gym-demo.uts` 中的 `DEMO_MODE`（默认 `false`）是唯一开关。改为 `true` 后，数据页只使用本地确定性生成的演示会话和演示动作库：
不读写云端、不读取本机真实训练记录、页面顶部和各卡片显示“演示数据”，点击记录不跳转详情。覆盖多个动作、多个日期、同日多场训练、热身组 / 未完成组、
单数据点（杠铃推举）、无数据（绳索夹胸、杠铃弯举）、不支持重量指标（引体向上、平板支撑）、缺少动作 ID 的旧记录。
`false` 时没有数据就显示空状态，不会回退到演示数据。

## 开始 / 继续训练与日期（修复）

- 日期来源：新训练的 `date` / `startedAt` 只取 `createSession(now)` 传入的点击时本地时间；日历选中日期只用于浏览，不参与任何创建 / 恢复 / 结束逻辑。
- 路由 `pages/workout/workout?id=<训练ID>` 只“打开已有训练”（`activateSession`），找不到则显示空状态，绝不创建训练；无 id 时只显示当前会话。
- 决策集中在 `services/workout-entry.uts` 的 `planStart`：今天开始的未结束训练 → 继续；其他日期的未结束草稿 → 弹窗让用户选择“继续原训练”或“保留它并开始今天的新训练”（旧草稿移入本机历史，不删除、不覆盖、不计入统计）；上次提交失败 → 先询问是否查看重试。
- 跨午夜：继续原训练保持原 ID 与开始时间，日期归属按开始的本地日期。
- `finishSession` 只允许结束当前会话中未结束的那一场（否则返回 `stale`）；没有已完成组时丢弃，不产生记录。
- 本机历史目标上限 30 条，超出时只淘汰已确认同步的结束记录；未同步记录与未结束草稿保留。

## 弹层与边距

- 弹层必须渲染在页面 `scroll-view` 之外（首页、数据页的弹层由页面容器放在 `scroll-view` 同级），否则 iOS 真机上 `position: fixed` 会被滚动容器及其 padding 限制成内容宽度。
- 统一外壳在 `styles/sheet.scss`：`sheet-backdrop`（视口级）、`sheet-panel`（全宽、顶部圆角 24px、内容左右 16px、不透明背景）、`.sheet-grabber`（36×4）。
- 页面左右边距 14px（`$gym-page-gutter`），卡片内边距 16px。
